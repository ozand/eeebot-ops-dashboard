# ADR-004 review: remaining planning/rest contract

Date: 2026-10-12  
Reviewed baseline: `2cd2928229cd370613c83855f949f71e123dd447`  
Disposition: **clarifications requested before approval of the remaining rest-reader contract**.

This is an independent reading of the existing proposal and implementation, not operator approval. ADR-004 remains Proposed. This document changes no reader, runtime, service, permission, branch protection or public projection; it authorizes no host access, merge or deployment.

## What is already delivered

PR #412 added a ledger-only planning observation. Its readers expose the last recorded planning event separately from execution cycles, keep current planning status unknown, and report rest fields as unavailable pending explicit reader-path approval. It does not implement the proposed read of `planner/rest_state.json`. The October 7 receipt describes an offline render of previously captured public HTML, not a new live host or browser probe. [S2, S4]

The acceptance register correctly separates this partial delivery from approval of the new rest path. The existing state-root/SSH identity approval is not approval of every file below that root. No new rest-file access should be inferred from this review or from a general request to improve the dashboard. [S1, S5]

## Review findings

### R1. Specify publication invalidation for rest-only changes

**Evidence:** ADR-004 describes a rest reader and typed projection, but not the publication gate for changes confined to that source. The baseline `compute_tree_digest()` hashes tree sources, the last 50 ledger lines, the lessons tail, projection version and generator identity. It does not hash rest state. The default staleness floor is six hours. [S1, S3]

**Consequence:** adding only a reader/renderer may leave a rest-only change unpublished until another digest input changes or the floor expires. A 900-second display threshold does not itself schedule publication. This is a gap in the proposed extension, not evidence that the intentionally ledger-only #412 implementation claims current rest state.

**Requested decision:** define the invalidation behavior when approved safe rest fields or their availability change with all existing digest inputs unchanged. Prefer a deterministic, bounded representation of the approved public semantics; do not use this as a reason to publish raw references, snapshots, reasons or credentials. Specify whether timestamp-only changes count, to avoid accidental publication on every read.

**Acceptance:** after a prior successful publish, a fixture changing only approved rest semantics exercises the real publisher decision and public rendering. An identical subsequent fixture remains a no-op within the configured floor. Missing/unreadable-to-readable transitions have explicit behavior. No real GitHub publication is required for this test.

### R2. Complete the time and static-page freshness contract

**Evidence:** the proposal distinguishes event time from file modification time and selects 900 seconds as presentation policy. It names 899/900/901-second tests, but does not explicitly define the equality case, future timestamps, or aging of an already rendered static page. The delivered #412 readers always keep current status unknown; this review does not reinterpret them as current-state evidence. [S1, S2]

**Requested decision:** keep observation time, source mtime and event time separate. Reading a file again must not make old source/event evidence fresh. State the exact threshold comparison and timezone rules; future/invalid times need an explicit clock-skew/unknown outcome rather than becoming fresh through a clamped zero age. Define how a static page crossing the threshold stops appearing current without borrowing freshness from unrelated files or the global footer. A deadline passing is not, by itself, proof that the runtime ended a rest.

**Acceptance:** deterministic clocks exercise both sources independently, the threshold boundary, missing timezone, future time, wall-clock rollback, expired deadline and an aging rendered page. No test depends on today's date or assumes actual bridge cadence from a tracked timer file.

### R3. Make bounds and validation an implementable contract

**Evidence:** ADR-004 requires bounded counters, a validated nested schema, exact wake kinds and path confinement, but leaves concrete byte/depth/counter limits and the unknown-field policy's scope unspecified. [S1]

**Requested decision:** name the reader's byte and structural limits, counter ceilings, accepted schema version and exact wake-kind vocabulary. Distinguish known private source fields that are validated but withheld from genuinely unknown schema fields. Preserve strict integer checks so booleans do not masquerade as counters. Document behavior for symlink/path escape, incomplete writes, oversized input, unknown schema and unreadable files. Reuse existing approved identity and roots; no permission widening.

**Acceptance:** local and remote implementations receive the same synthetic invalid-shape and limit fixtures. Serialized public HTML and JSON are checked for canaries in keys, values, references, snapshots, reasons and error text. Tests prove confinement and unknown/unavailable results without reading any actual host file.

### R4. Correct the read-scope wording and test inventory

The Context explicitly acknowledges a new relative file read, while "What this IS NOT" says it does not alter host reads. Clarify that the proposed extension adds one separately approved file read but no new identity, root, permissions or runtime mutation; until approval it performs no such read. [S1]

The proposed Test Contract names `tests/test_planning_activity.py` cases as not yet written. A partial ledger-only regression already exists under `tests/test_techtree_viewer.py::test_planning_activity_ledger_reader_projection_and_panel_do_not_invent_cycles`. Keep the remaining rest contract separate rather than calling all planning tests absent or all #395 acceptance complete. [S1, S2]

## Acceptance matrix for the remaining extension

The rows below are **proposed verification**, not executed results or approval to add a source.

| Fixture / transition | Required observable distinction |
|---|---|
| Rest path not approved | No new file read; explicit unavailable-pending-approval state |
| Approved source absent | Absent/unavailable, not inactive and not measured zero |
| Read error, partial write or malformed schema | Unknown; sanitized diagnostics; no invented current state |
| Valid schema with `active_rest: null` | Explicit no-active-rest evidence only under the accepted freshness contract |
| Valid object with measured zero counters | Measured zero remains distinct from missing/withheld |
| Stale valid object | Last-recorded fields remain historical; current status unknown |
| Fresh file with old planning event, or the reverse | Separate source/event ages; neither repairs the other |
| Ages 899 / 900 / 901 seconds | Exact agreed boundary, using an injected clock |
| Future/invalid timestamp or backward clock jump | Explicit uncertainty; no fabricated current observation |
| Deadline passes without new source evidence | No inferred runtime transition or fabricated cycle |
| Only approved rest semantics change | Agreed publication invalidation; next identical state can skip |
| Canaries, unknown fields or path escape | No private material in any public output; unsafe read refused |
| Same fixture through local and remote readers | Equivalent states, safe fields and privacy behavior |
| Rest-held observation with no execution start | No synthetic cycle and no active-work claim |

Full-path checks should use real projection/render/publisher-decision functions with external writes stubbed. Browser evidence must inspect the rendered state, not merely helper return values. These tests supplement, rather than replace, existing ADR-036 privacy tests.

## Implementation and refactoring boundary

After explicit operator disposition, implement the accepted remaining contract in a separate scoped PR with failing tests first. Keep #395 independent from the digest I/O optimization in #418/#419: that optimization preserves the current digest semantics and does not add rest invalidation or new inputs.

Do not use this extension as implicit authorization to delete the legacy renderer. #381 still needs the separate remove-versus-restore decision recorded in the acceptance register. A later decomposition should first preserve the real public entry points, local/remote parity, import/deployment layout and public/private projection tests. [S5]

## Review method and limitations

Read the pinned ADR, #412 implementation diff and regression, digest implementation, acceptance register and the named #395 receipt. No new host probe, screenshot capture, live publication or independent full-system privacy audit was performed. The proposed tests above were not implemented or run by this documentation review. It does not change ADR status or close #395.
